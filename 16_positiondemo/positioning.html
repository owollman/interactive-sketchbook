positioning elements

Static

default, as-is behavior

Relative

this positions a child relative to its parent. by giving an element a relative position, we can place it outside the normal flow of where it would be- but it still impacts other elements

Absolute

this takes the element out of the line up and no longer impacts elements around it, BUT you have to apply position:relative to a parent container

Fixed

positioned in relation to the browser window, it just stays put!

***Sticky***

this one is a little more advanced, and we won’t get into it yet, but perhaps challenge yourself and your project to see if you can figure it out?


Next up: z-index

this is how we control layering when we are using positioning. if an element has a position, you can add a z-index, the larger the number the closer to the top.
0=bottom 100=top
think of z-index like the “bring to front” or “send to back” in design software.

Reflection

Absolute positioning made the most sense to me just because I can manually decide the locations of each object with little to no objection from the other objects on the screen. I feel like with relative positioning if you change one position it will impact everything and then you have to figure out which object to adjust to compensate. In my sketchbook I hope to use positioning to make the home page more interesting to look at. Right now it is a solid color and a little plain compared with my other pages. I'd like to layer shapes underneath some of the H tags to define certain sections more than others.

I think I am still confused about flexbox and flex containers. So far it has been a process of trial and error to figure out which flex direction to put or how to align items or what a flex-wrap does. I think positioning itself was very easy for me to understand but I might make it harder for myself by not understanding exactly how flexbox works without the 20 or so minutes of trial and error.
